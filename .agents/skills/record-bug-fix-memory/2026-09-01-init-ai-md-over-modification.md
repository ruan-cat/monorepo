# 2026-09-01 init-ai-md 技能过度修改

## 1. 问题现象

在升级 `init-ai-md` 技能时，原本只需要调整 canonical 文档、旧文件重定向、模板删除、技能迁移和版本号，却把原有的执行示例、部署分支、技能表说明、双层存储说明和正常标点大范围重写。用户需要多次指出“过度删改”和无意义的标点变化，才能恢复到可接受状态。

## 2. 实际根因

把“破坏性行为变更”误判成了“整份技能重构”。没有先以 `HEAD` 版本建立受保护基线，也没有在第一次编辑前完整检查 staged 与 unstaged diff，导致正常内容被压缩、改写和重新措辞。随后又把“统一 AGENTS.md 落点”错误扩大为所有相邻段落都要重新设计。

## 3. 关键误导点

- 误把“让新规则清晰”理解为“可以重写旧规则”。
- 只关注新行为是否出现，没有逐段确认旧行为是否仍然保留。
- 进行无价值的中文润色和引号规范化，例如把原文直引号改成中文弯引号。
- 早期只看工作树 diff，忽略了本仓库当时已有的 staged diff；直到用户截图指出具体行，才定位到标点漂移。

## 4. 有效修复

1. 将 `init-ai-md/SKILL.md` 恢复到 `HEAD` 原文作为基线。
2. 只重新应用用户明确要求的变更：`AGENTS.md` 唯一主文档、`CLAUDE.md`/`GEMINI.md` 重定向、删除废弃模板、迁移或无条件安装 `record-bug-fix-memory`、版本 `22.0.0`、中英双语 description。
3. 保留原有扫描、交互选择、差异补全、部署分支、技能表、执行示例、模板规范和验证规则。
4. 恢复原文标点和措辞，不做无关润色；目标文件 diff 收敛到 95 行新增、90 行删除。

## 5. 验证方式

- `MINIMAL_DIFF_ACCEPTANCE=PASS`
- `git diff --check` 通过。
- `pnpm run typecheck:ai-plugins` 退出码 0。
- `pnpm exec vitest run packages/skill-router-mcp/tests/skill-registry.test.ts` 退出码 0。
- 复核技能表更新策略、内置技能部署详细说明和图中直引号均与预期一致。

## 6. 后续约束

- 修改现有 skill 前，先读取 `git diff` 和 `git diff --cached`，确认 staged/unstaged 边界；不得只看当前工作树的一种 diff。
- 先列出“必须改变”和“必须保持不变”的内容，再从 `HEAD` 原文做定点 patch；禁止以“重写更清晰”为理由重排正常章节。
- 用户只要求行为语义变化时，保留原有标题、段落、示例、分支和标点；除非该处与新行为直接冲突，否则不改。
- 对每个章节执行逐段回读和局部 diff 检查；看到无关的引号、空格、措辞变化立即撤销。
- 变更完成前报告实际 diff 规模和验证证据；不要用“看起来一致”替代命令输出。
