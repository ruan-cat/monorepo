# 2026-08-10 init-prettier-git-hooks 过度工程复盘

## 现象

用户要升级对外分发的 `init-prettier-git-hooks` 技能，并要求下一次调用时能识别旧的 lint-md 字符串插件配置、由 AI 完成精准替换。实现过程却先把技能错误扩展成独立迁移产品：设计并拟实现 `scripts/migrate.mjs`、`src/` 分层、事务与运行时校验、大量夹具和多轮子代理复核，消耗了大量 token 和沟通成本。用户明确指出这违背了“技能内 AI 直接操作”的目标后，才删除该架构并收缩。

## 根因

- 把“批量识别与替换”误解为必须提供确定性 CLI，而没有先判断该行为本应由调用技能的 AI 在目标项目中完成。
- 没有把用户后续的“完全交给 skill 内的 AI 操作流程完成”当作对既有 spec/plan 的立即替代，导致已过度细化的方案继续占用注意力。
- 用脚本、测试矩阵和重复复核替代了对交付模型的判断；验证了大量实现细节，却没有优先验证“这是否仍是用户要的技能”。
- 虽已存在“简洁优先、流程服务目标”的仓库规则，但没有在方案评审点把它们变成可执行的止损门禁。

## 关键误导点

“旧配置替换”看起来像程序转换问题，但本次真实约束是：技能安装后由 AI 读取具体项目、保留本地差异、在复杂配置时询问用户。为此编写通用迁移器不仅不能降低风险，反而制造了静态解析、事务、锁文件、Hook 所有权等不存在于用户目标中的边际条件。

## 有效纠偏

收缩为 `SKILL.md` 加五份配置模板；由技能明确候选扫描、ESM 静态配置的精准替换条件、非 ESM/动态/多配置的人工分流，以及会改动暂存区或 Hook 的授权边界。删除本次新引入的 `scripts/`、`src/` 和迁移器测试夹具；保留必要的静态契约测试和事故注释。

## 验证

- 目标技能目录不包含 `scripts/`、`src/` 或迁移器夹具。
- 定向 Vitest 静态契约测试通过。
- `prettier --check`、三个 MJS 模板的 `node --check` 与 `git diff --check` 通过。
- 独立复核确认：技能允许 AI 审计后直接精准修改，未再分发独立迁移 CLI；`--experimental-cli` 命令均带且仅带一个 `--no-parallel`。

## 后续约束

1. 对外分发 skill 先写一句“交付模型判定”：是 AI 操作流程还是随 skill 分发的确定性工具。没有明确、不可由 AI 安全完成的重复性操作证据时，默认前者，禁止新增脚本架构。
2. 用户说“太复杂”“直接由 AI 完成”“不要脚本”时，立刻废止冲突 spec/plan 和未完成子任务；先给出收缩后的文件清单与一组验收命令，再继续实施，不得在旧架构上追加修补轮次。
3. 测试只验证技能的关键、易回归契约；不得为了测试而把文档型 skill 演变成需要运行时、事务或大量夹具的产品。
4. 多代理任务默认限定为一次探索、一次编辑、一次独立复核；只有发现影响用户目标的明确 P1 才开修复轮，并且修复前重新检查是否应删除需求而非补代码。
5. 声称完成前，除测试外必须逐项对照用户最近一次明确的交付模型和禁止项；二者冲突时，以用户最新决定为准。
