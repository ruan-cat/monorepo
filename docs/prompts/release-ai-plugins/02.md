#### 强制必须写 compatibilityDate 的对象形式，且带注释

必须强制写成：

```txt
compatibilityDate: {
	// https://v3.nitro.build/deploy/providers/cloudflare
	cloudflare: "2024-09-19",
	// https://nitro.build/deploy/providers/vercel#observability
	vercel: "2024-09-19",
}
```

而不是写成单纯的： `compatibilityDate: "2024-09-19"` 。我要求必须要带上清晰明确的部署平台，以及额外的注释。我希望多暴露，携带更多的信息出来。尽管 `compatibilityDate: "2024-09-19"` 配置很简单，但是这传达的信息很少，不利于人类阅读，学习，和维护。

### 纯 nitro 接口开发的项目需要对外暴露接口文档

首先，需要先判断这个 nitro 配置是否是 vite 全栈项目配置，还是单纯的 nitro api 接口形式，先判断项目类型，再开始配置。

如果确定项目是纯 api 接口项目，那么就提供接口文档配置，举例如下：

```txt
import pkg from "./package.json" with { type: "json" };

experimental: {
	openAPI: true,
},

openAPI: {
	meta: {
		title: "learn-nitro-starter API",
		description: "Nitro v3 学习项目接口文档",
		version: pkg.version,
	},
	production: "prerender",
	route: "/openapi.json",
	ui: {
		scalar: {
			route: "/scalar",
		},
	},
},
```

除了你的 openAPI.meta.title 和 openAPI.meta.description 这两个字段需要看情况发挥以外，其他的配置都应该是固定的配置。
其中，openAPI.meta.version 的写法可以稍微变通一下，总之必须要获取来自 package.json 的版本信息。如果 package.json 没有版本信息，你就自己补充一个。
