# 工具链升级验收

## ADDED Requirements

### Requirement: 阶段验收必须有命令证据

每个迁移 checkpoint MUST 绑定可复现的安装、构建、测试或版本检查命令，并记录真实输出摘要。

#### 场景：阶段未达到门槛

- **当** 任一必需命令失败或输出无法解释
- **则** checkpoint 保持未通过并停止扩张范围
- **并且** 失败原因、影响范围和下一步动作写入长任务状态工件

### Requirement: 全链路验收覆盖核心与文档

最终验收 MUST 同时覆盖核心包构建、显式 Vitest projects、entrypoints、文档构建和 CI 等价命令。

#### 场景：核心测试通过但文档失败

- **当** 核心包和 Vitest projects 通过而文档构建失败
- **则** 结果只能标记为核心轨道阶段性通过
- **并且** 不得宣称全仓 Vite 8 统一

### Requirement: 版本树异常可定位

验收 MUST 检查 `pnpm why vite`、`vite --version` 和 `vitest --version`，并解释每个保留的旧版本来源。

#### 场景：锁中存在多个 Vite 主版本

- **当** 文档框架或插件仍引入 Vite 5/6
- **则** 报告列出依赖链和收敛条件
- **并且** 不以删除锁中旧版本作为唯一成功标准

### Requirement: 最终完成必须满足全链路出口

只有当版本与配置入口、核心构建、文档构建、测试 projects、CI 等价命令和业务导出均有实际证据时，系统 MUST 才能将变更标记为全仓升级完成。

#### 场景：只有核心工具链通过

- **当** 根 Vite/Vitest 与核心包通过，但文档、entrypoints 或 CI 等价命令缺少证据
- **则** 结果只能标记为阶段性通过
- **并且** 必须列出剩余轨道和解除条件

### Requirement: 失败归属必须可回溯

每个阶段 MUST 能区分既有基线失败、迁移引入回归和外部上游阻塞，并保留对应命令、影响范围和回滚边界。

#### 场景：多个轨道同时失败

- **当** 测试、构建和文档命令同时失败且原因尚未分离
- **则** 停止扩大改动范围并回到最近绿色边界
- **并且** 不得通过扩大 glob、跳过测试或强制 alias 把失败合并成“环境问题”
