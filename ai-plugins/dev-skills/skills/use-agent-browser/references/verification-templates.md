# 验收与报告模板

> 本文是 use-agent-browser 技能的参考层：可直接复制填空的验收记录模板。截图默认落系统临时目录（agent-browser 默认在用户主目录下 `~/.agent-browser/tmp/screenshots/`），确需版本化证据时经用户确认后复制进对应 evidence 目录并单独提交。

## 1. 视觉验证报告模板

```markdown
## 视觉验证报告

- **日期**：YYYY-MM-DD
- **验证人**：AI Agent / 人类
- **被测版本**：commit SHA 或文档站版本
- **agent-browser 版本**：x.x.x（`agent-browser --version`）
- **浏览器来源**：agent-browser 自动启动 / 本机 Chrome CDP 接管（端口 xxxx）/ headless 连接

### 验证结果

| #   | 场景         | 状态  | 截图                      | 备注                      |
| :-- | :----------- | :---- | :------------------------ | :------------------------ |
| V1  | 默认主题首屏 | ✅/❌ | <task>-dev-v1-default.png | 关键取值或差异说明        |
| V2  | 主题切换交互 | ✅/❌ | <task>-dev-v2-toggle.png  | 点击 @eN 后状态           |
| V3  | 目标元素特写 | ✅/❌ | <task>-dev-v3-target.png  | scrollintoview 后视口截图 |
```

每行截图必须是**目标元素滚入视口后的视口截图且已实际查看**；全页缩略图与加载统计只能作辅助列。

## 2. 生产验收八要素清单

生产环境验收记录必须八项齐全，缺一项先补齐再下结论：

```markdown
- 浏览器可执行程序：<agent-browser 自动启动 / 本机 chrome.exe 路径>
- CDP 端口/会话类型：<9222 CDP 接管 / 命名会话 <name> / headless 连接>
- 精确 URL：<原样记录，含协议路径与锚点>
- 截图路径：<临时目录路径，逐张列出>
- 部署 ID：<部署平台 deployment id，或「本地未部署」>
- 提交 SHA：<被测 commit>
- 加载统计：<资源数/加载数/失败数>
- 视觉结论：<逐场景通过/不通过 + 人工判读说明>
```

## 3. 流式/长任务四状态记录模板

AI 对话、流式接口、长耗时任务的验收按状态逐项报告，不把前一项包装成后一项：

```markdown
| 状态           | 证据                            | 结论                       |
| :------------- | :------------------------------ | :------------------------- |
| 请求已发出     | network 请求记录                | ✅/❌                      |
| 中间产物已渲染 | 首帧/来源片段截图               | ✅/❌                      |
| 取消成功       | 停止按钮点击后状态收敛截图      | ✅/❌                      |
| 完整结束       | 完整回答 + 来源链接跳转锚点验证 | ✅/❌ / 未在本次尝试中结束 |
```

「取消链路通过、完整回答流未结束」是合法且必须如实记录的中间结论。

## 4. 执行节奏模板：smoke → 分批矩阵 → 单独 fullscreen

```markdown
### smoke（首轮，失败即停）

- [ ] 确认浏览器实例归属（本会话专用 tab，不碰用户页面）
- [ ] set viewport 1920 1080（视口固定是第一步）
- [ ] open <URL> → wait --load networkidle → get title
- [ ] eval 检查根节点、路由、关键标题、canvas 尺寸、console error 数
- [ ] 至多一张 smoke 截图
- smoke 失败时停止扩大矩阵，先修 URL、端口、等待条件或页面错误

### 分批矩阵（smoke 通过后）

- [ ] 每批 2-3 个场景，批内：等待 → 交互 → 度量 → 截图 → 记录
- [ ] dev 与 preview 双端对比时：同路由、同视口、同等待、同度量脚本；对比顺序双向（先 dev 后 preview，再用同一检查项回看 dev）

### 单独 fullscreen（如需要）

- [ ] 处理窗口状态后再全屏（最小化窗口直接全屏会报错）
- [ ] fullscreen 截图单独归档命名
```

完成检查清单：确认可见非 headless（动画页）/ smoke 有记录 / 分批有界 / fullscreen 单独 / 交互证据在 / 双端对比双向 / 截图在临时目录且命名带来源 / 只关自己的资源 / 结束前复查端口 PID profile / 最终说明含证据路径与未覆盖风险。

## 5. 证据 supersede 标记写法

新验收完成后，在工件中给旧证据打标记，避免过期证据误导：

```markdown
- 2026-MM-DD 修复前证据：<旧结论摘要>……该证据已被 <新验收> supersede。
- 2026-MM-DD 修复后验收：<新结论 + 新证据路径>。
```

## 6. 工件登记模板（如使用 OpenSpec 工作流）

同一份浏览器验收在三处工件中的登记写法：

```markdown
<!-- tasks.md 勾选行 -->

- [x] [验证] `agent-browser` - 可见浏览器打开生产首页与目标页面，确认导航/主题/SSR 内容/关键交互；浏览器 errors 输出为空。

<!-- agent-progress.md checkpoint 行 -->

浏览器证据：生产首页与目标页通过 agent-browser，可见导航、主题、SSR 内容与关键交互，errors 为空。

<!-- agent-findings.md 发现条目（F 条目固定三段） -->

- F<n> <结论一句话>
  - 证据：<命令 + 截图路径 + 关键输出>
  - 后续：<未覆盖项或 supersede 指向>
```

## 7. 截图命名规范

- 默认目录：系统临时目录（不入仓库）。
- 文件名：`<任务前缀>-<来源>-<场景>-<时间戳>.png`，来源取值 `dev` / `preview` / `production` / `fullscreen`——来源必须出现在文件名里，防止把预览截图当生产证据。
- 默认压缩格式（JPEG）优先，特写判读场景用 PNG。
- 任务结束前：已查看并记录的截图按需归档，其余删除；确需进仓库的证据先经用户确认。

## 8. 三层验收链路

同一缺陷要过三层证据，层层不可互相替代：

| 层级        | 必须检查                                     | 不能替代什么                   |
| :---------- | :------------------------------------------- | :----------------------------- |
| 转换/单元层 | 子包测试、真实 fixture、导出产物检查         | 不能替代页面视觉               |
| 本地页面层  | 本地打开原始路径、目标元素视口截图、实际判读 | 不能替代生产容器               |
| 生产页面层  | 同一路径与截图复验 + 部署 ID / commit SHA    | 不能用旧部署或资源请求成功替代 |

## 9. 验证口径

一次「通过」至少同时具备：状态码/请求结果、标题与正文断言、水合与渲染判定、桌面视口截图、至少一个交互闭环——缺一不可。UI 配置类修改必须过浏览器视觉验收，源码分支推断不作为依据。
