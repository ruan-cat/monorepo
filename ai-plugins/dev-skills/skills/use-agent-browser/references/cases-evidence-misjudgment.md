# 案例集：证据误判与验收缺口

> use-agent-browser 技能参考层。案例均来自真实项目实战复盘（已脱敏）。这些案例的共同模式：**证据不足以支撑结论时，结论被提前或错误地宣告**。命令语法以 `agent-browser skills get core` 为最终权威。

## 案例 1：naturalWidth 只证明加载，不证明视觉正确

- **现象**：验收只检查 `img.naturalWidth` 与文字可见，全部通过；但页面上存在图形重复图层、错位与裁断。
- **根因**：加载状态与视觉正确性是两个断言；`naturalWidth > 0` 只能证明资源加载成功。
- **关键误导点**：把「最容易自动化检查的指标」当成了「视觉通过的充分条件」。
- **有效修复**：视觉判定固定为「目标元素 `scrollintoview` + 视口截图 + 执行者实际查看截图」；加载统计降级为辅助证据。
- **验证方式**：按新标准复验，逐图截图判读，发现并修复了纯加载检查漏掉的缺陷。
- **后续约束**：任何「视觉通过」结论必须有目标元素视口截图支撑；报告里不允许只出现加载统计。

## 案例 2：截图时机过早 = 假故障

- **现象**：截图显示面板「缺失」，据此险些启动大规模组件重构。
- **根因**：截图前未固定视口（1920x1080）、未等 loading 消失（3-4s）、未等入场动画完成（2-3s）、菜单切换后未等待就截图。
- **关键误导点**：把「截图里没有」当成「页面上没有」；过早截图是验收脚本的错，不是页面的错。
- **有效修复**：先 `set viewport` 固定视口，按等待策略（loading 消失 + 动画自然完成）等待后再截图；禁用「未冻结动画、未固定视口的截图」作为缺失判定依据。
- **验证方式**：按正确时机重截，面板完整出现。
- **后续约束**：任何「组件缺失/页面未渲染」结论前，先自检截图时机四要素（视口、loading、动画、切换等待）。

## 案例 3：a11y 快照能读到视觉隐藏的 DOM

- **现象**：loading 遮罩用 `opacity: 0` 隐藏后，快照仍能读到其文本节点；而截图里 loading 已不可见。
- **根因**：可访问性树以 DOM 为准，`opacity` 只是视觉隐藏；快照与截图是两套证据。
- **关键误导点**：用快照存在推断「视觉上还在」，或用截图不存在推断「DOM 已移除」。
- **有效修复**：结构判定用快照、视觉判定用截图，两者不一致时分开记录，不得互相替代。
- **验证方式**：同一页面双证据对照，结论分别成立。
- **后续约束**：涉及「元素是否可见」的判定必须落到截图 + 实际查看；涉及「元素是否存在/可交互」才用快照。

## 案例 4：READY / HTTP 200 / 预览保护页都不是应用证据

- **现象**：部署平台显示 READY 但浏览器访问返回 500；预览域名打开的是访问保护页而非应用；单次 200 被当成整页通过。
- **根因**：部署状态、HTTP 状态、应用运行时状态是三层不同的证据。
- **关键误导点**：用最容易拿到的状态（READY/200/预览可达）替代完整链路验收。
- **有效修复**：生产验收以「生产域名 + agent-browser 实操」为准：页面导航、真实 API、关键交互、errors 为空逐项取证；READY 与单次 200 不得替代完整链路。
- **验证方式**：READY + 浏览器 500 的组合被如实记录为「未完成」，回修后才关闭任务。
- **后续约束**：预览域名保护页、旧部署、资源请求成功均不得作为应用通过证据。

## 案例 5：console 是第一信号，且「无错」不等于「正常」

- **现象**：整站交互全死但 console 干净；另一场景图表静默降级，只有 console 提示 series 未注册，截图像素完全看不出。
- **根因**：模块脚本执行失败不一定走 `console.error`；静默降级只产生 warn/info 级提示。
- **关键误导点**：视觉症状先查 CSS、console 干净就排除前端问题。
- **有效修复**：先查 console（含 warn）；「无错且不水合」时用 `!!document.querySelector('#__nuxt').__vue_app__` 判定挂载，动态 `import(entrySrc + '?v=diag')` 抓真实模块错误；需要导入链时用 CDP `Network.requestWillBeSent` 的 `initiator.url` 定位导入方。
- **验证方式**：动态 import 抓到真实 SyntaxError；CDP initiator 指向了此前被排除的错误依赖，避免修错对象。
- **后续约束**：console 捕获不可靠时降级为 CDP 直连抓 `pageerror`，不要凭「console 没输出」下「无错」结论。

## 案例 6：流式任务的部分成功不得包装为完整成功

- **现象**：AI 对话验收中「停止生成」点击后状态收敛、已收内容保留，但完整回答流从未在本次尝试中走完。
- **根因**：流式任务包含「请求已发出 / 中间产物已渲染 / 取消成功 / 完整结束」四个独立状态。
- **关键误导点**：前两项通过 + HTTP 200，容易被写成「功能验收通过」。
- **有效修复**：四状态逐项记录；「取消链路通过、完整回答流未在本次尝试中结束」是合法且必须如实写出的中间结论。
- **验证方式**：后续会话补充完整回答流证据后才关闭该项。
- **后续约束**：参考资料出现或 HTTP 200 不得替代完整回答流结论（模板见 `verification-templates.md` 第 3 节）。

## 案例 7：单样本通过不可外推为全量合格

- **现象**：某一类资源的单个生产样本验收通过，任务清单里其余覆盖项被尝试用该样本外推关闭。
- **根因**：覆盖范围与样本数是验收结论的边界条件。
- **关键误导点**：「同类应该都没问题」。
- **有效修复**：明确标注「6.x-y 已完成，6.x-z 仍是未完成的全量质量门禁，不能由单个生产样本外推关闭」；逐项补齐覆盖清单。
- **验证方式**：未覆盖项保持未勾选，直到逐项证据齐全。
- **后续约束**：验收结论必须携带覆盖范围说明；未完成项不得静默合并进已完成结论。

## 案例 8：截图落在仓库外导致归档证据缺图

- **现象**：归档时发现 evidence 目录没有截图；git 历史里从未包含图片路径。
- **根因**：agent-browser 截图默认存放在用户主目录下 `~/.agent-browser/tmp/screenshots/`（仓库外），归档动作只移动了仓库内文件。
- **关键误导点**：先怀疑归档过程删了文件；实际是截图从未进过仓库。
- **有效修复**：核对归档前后 evidence 文件清单一致后，确认截图在临时目录；需要版本化的截图经用户确认后复制进 archive/evidence 并单独提交。
- **验证方式**：`git log` 与 evidence 清单逐项比对，确认无丢失；补交的截图在后续归档中可追溯。
- **后续约束**：需要成为长期证据的截图，当场决定归宿（临时目录仅供判读，版本化需显式动作）。

## 案例 9：擅自改写用户 URL 导致 404 误判

- **现象**：本地页面验收时擅自去掉用户给定路径的后缀并做百分号编码后访问，得到 404；调试时间浪费在「修复」并不存在的站点问题上。
- **根因**：被测 URL 是验收契约的一部分；自行「优化」后，验收对象已经不再是用户指定的那个。
- **关键误导点**：404 看起来像站点路由问题，实际访问的是一条从未存在的路径。
- **有效修复**：原样拼接并打开用户给定的精确 URL；失败后记录 HTTP 状态、路由配置与实际文件路径，提出受证据约束的替代路径，经确认后才使用。
- **验证方式**：原样 URL 打开正常返回，后续验收全部基于原样 URL。
- **后续约束**：URL 是契约不是建议；任何改写必须先暴露证据并获确认（对应 SKILL.md 不可跳过纪律第 2 条的案例背景）。

## 案例 10：桌面验收不能关闭移动视口门禁

- **现象**：桌面视口验收全部通过后，移动视口的菜单展开、多栏访问与组件页浏览证据仍缺失，任务无法完全关闭。
- **根因**：视口是覆盖维度之一；桌面证据与移动证据互不可替代，响应式布局在两种视口下的渲染路径不同。
- **关键误导点**：「桌面过了，移动应该差不多」。
- **有效修复**：把移动视口验收保留为显式未完成门禁，逐项补齐移动端证据后才关闭。
- **验证方式**：任务清单保持显式未勾选状态，直到移动端逐项取证。
- **后续约束**：验收结论必须写明覆盖的视口维度；只覆盖桌面时明确标注移动项未验，不与案例 7 的「单样本外推」混为一谈（一个是样本数、一个是覆盖维度）。
