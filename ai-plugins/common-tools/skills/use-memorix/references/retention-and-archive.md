# Retention 与归档硬门

本文件只处理「哪些记忆可以退出 active retrieval」。写入、检索、健康检查不在本文件。归档是高风险动作，宁可少做，不可误做。

## 形成候选的唯一条件

满足以下任一条件，才允许进入 archive candidate：

1. 当前 Memorix runtime 明确返回官方 `archive-candidate` 标记。
2. 操作者能给出明确后继替代关系：被替代 ref、后继 ref、替代理由，三者齐全。

以下任一单项**都不足以**形成候选：

| 弱信号       | 为什么不够                                   |
| :----------- | :------------------------------------------- |
| stale        | 长期未访问不等于失效，可能只是低频高价值     |
| age          | 创建久远与正确性无关                         |
| low-evidence | 证据少可能是新记录，也可能是关键决策         |
| orphan       | 关联缺失可能是引用重建未跑，不等于内容无价值 |

多个弱信号叠加也不自动等价于后继替代；仍需官方候选或明确 successor。不要用「看起来没用了」作为理由。

## 执行顺序（七步，不可跳）

1. 只读列出候选及证据：id、标题、类型、最后访问、当前状态、候选来源。
2. 生成可恢复快照，或执行官方 dry-run / preview。
3. 若当前命令没有 preview：导出脱敏清单（id、状态、后继关系），不导出正文。
4. 向用户展示「将从 active retrieval 退出的记录」清单，逐条说明理由。
5. 获得明确授权；未获授权即停止，不做任何写入。
6. 优先把状态标为 `archived`，不做物理删除。
7. 回读验证：状态确为 archived，active 搜索结果确实不再返回它。

物理删除只在用户另行明确要求、且已存在可恢复点时才考虑。删除前再确认一次目标与备份位置。

## cleanup / purge / VACUUM 边界

| 动作    | 性质     | 约束                                  |
| :------ | :------- | :------------------------------------ |
| archive | 状态变更 | 候选硬门 + 快照/预演 + 授权           |
| cleanup | 批量清理 | 先预演数量与日期边界，再单独确认      |
| purge   | 物理删除 | 必须具备恢复点；不与 archive 混为一谈 |
| VACUUM  | 存储重写 | 展示目标库、锁行为、停止条件后确认    |

禁止把 cleanup、purge 或 VACUUM 伪装成 archive 的实现细节。用户说「归档一下」时，默认只做 archived 状态变更。

## 存储边界

- 不把 `MEMORIX_DATA_DIR` 指向项目 `.memorix/`。项目 `.memorix/` 只承载 `hooks.json` 与 `golden-set/`。
- 归档前确认操作的是哪个数据库文件，避免误对副本或临时库执行。
- 候选 `.local/` 的清理属于 retrieval 域的留存策略，不与 archive 混在一起。

## 回滚与验证

| 场景             | 验证方式                                              |
| :--------------- | :---------------------------------------------------- |
| 刚归档           | detail 查状态；search 确认不再命中                    |
| 误归档           | 用 resolve 恢复状态（写入，需确认），不要直接改库文件 |
| 快照后失败       | 说明快照位置与恢复步骤；不静默重试                    |
| cleanup 预演不符 | 中止，重新计算日期边界与数量                          |

任何一步无法验证，就把任务标为未完成，不要用「应该已归档」结案。
