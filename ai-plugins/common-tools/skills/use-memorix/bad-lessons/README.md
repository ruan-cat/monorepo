# 糟糕经验教训

这里只放已经有结论、但会过期的历史报告。不是现行操作手册。

现行规则在 `SKILL.md` 和 `references/`。两边冲突时，以那两处为准。本目录不能覆盖它们，也不能单独成为检索、存储或黄金集的操作合同。

## 使用前

1. 先读完本文件，再打开单份报告。
2. 报告开头的「成立前提」必须全部成立。有一条对不上，这份报告本次作废。
3. 再跑该报告自己的「新鲜度门」。门没过，本次作废。
4. 作废的意思是：不得引用它的根因，不得安排它里面的待办，不得把它写进黄金集或新的记忆正文。文件留在目录里，供以后核对「曾经这么错过」。

作废不是删文件。文件正文不会在上游修复合并时自动改写。维护者标记只供人读，不是真值。真值是这一次阅读时前提和新鲜度门的结果。

## 什么时候整份报告作废

报告里会写自己的作废条件。目录级的共同条件是：

- 报告描述的代码行为，在当前 `memorix --version` 对应的安装包里已经不存在。
- 报告描述的旧数据也已经按正确身份重写或删除。代码修好但旧行还在时，只作废「代码仍会继续写错」这一句，不作废「这几条旧行仍会让查询看不见」。旧行处理完，整份报告作废。

版本号变了，不能沿用写作时的结论。本技能不把某个版本号写成永久真值。
